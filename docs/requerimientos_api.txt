## **Fase 1: Gestión de Usuarios (Completada)**

### **Endpoint de Registro de Usuario**
*   **URL:** `/api/usuarios/register`
*   **Método:** `POST`
*   **Descripción:** Registra un nuevo usuario.
*   **Cuerpo de la Petición (JSON):** `UsuarioRegistroDTO`
*   **Respuestas Posibles:**
    *   `201 CREATED`: Usuario creado exitosamente.
    *   `400 BAD REQUEST`: Datos de entrada inválidos (RUT, email, etc.).
    *   `409 CONFLICT`: El RUT o el email ya existen.

### **Endpoint de Login de Usuario**
*   **URL:** `/api/usuarios/login`
*   **Método:** `POST`
*   **Descripción:** Autentica a un usuario con su email y contraseña.
*   **Cuerpo de la Petición (JSON):** `UsuarioLoginDTO`
*   **Respuestas Posibles:**
    *   `200 OK`: Autenticación correcta. Devuelve el objeto `Usuario` (sin contraseña).
    *   `401 UNAUTHORIZED`: Credenciales inválidas.

## **Fase 2: Gestión de Movimientos (Completada)**

**Objetivo:** Toda la lógica de ingresos y gastos, que antes se gestionaba localmente en la app (`DatabaseHelper.kt`), ha sido migrada con éxito al backend. Esto centraliza los datos y permite la persistencia y sincronización entre dispositivos. La base de datos local ha sido depurada de este código.

### **Endpoint para Registrar un Movimiento**
*   **URL:** `/api/movimientos`
*   **Método:** `POST`
*   **Descripción:** Registra un nuevo ingreso o gasto para un usuario.
*   **Cuerpo de la Petición (JSON):** `MovimientoRegistroDTO`
*   **Respuestas Posibles:**
    *   `201 CREATED`: Movimiento registrado. Devuelve el `MovimientoResponseDTO` creado.
    *   `404 NOT FOUND`: El usuario especificado en el DTO no existe.

### **Endpoint para Obtener Historial de Movimientos**
*   **URL:** `/api/movimientos/usuario/{rut}`
*   **Método:** `GET`
*   **Descripción:** Obtiene la lista completa de movimientos de un usuario, ordenados del más reciente al más antiguo.
*   **Respuestas Posibles:**
    *   `200 OK`: Devuelve una lista de `MovimientoResponseDTO`.
    *   `404 NOT FOUND`: El usuario con el RUT especificado no existe.

### **Endpoint para Obtener Saldo Actual**
*   **URL:** `/api/saldos/{rut}`
*   **Método:** `GET`
*   **Descripción:** Calcula y devuelve el saldo actual total de un usuario.
*   **Respuestas Posibles:**
    *   `200 OK`: Devuelve un objeto JSON con el saldo. `{"saldo": 1234.56}`.
    *   `404 NOT FOUND`: El usuario con el RUT especificado no existe.

## 6. Integración de APIs Externas

- **Acceso:** A través del ítem "Mercado" en la barra de navegación inferior.

### 6.2. API de Conversión de Monedas (frankfurter.app)

Se ha implementado un conversor de monedas global.

**Arquitectura Implementada:**

- **Capa de Datos (`/api` y `/model/dto`):**
    - **`ConversionResponseDTO.kt`:** Modelo para la respuesta de la conversión.
    - **`FrankfurterApiService.kt`:** Interfaz de Retrofit con los endpoints `getCurrencies` y `getLatestConversion`.
    - **`FrankfurterRetrofitClient.kt`:** Cliente de Retrofit configurado con la URL base `https://api.frankfurter.app/`.

- **Capa de Lógica (`/viewmodel`):**
    - **`ConverterViewModel.kt`:** Nuevo ViewModel que gestiona la carga de la lista de monedas, el estado de la UI (`ConverterUiState`) y la lógica para realizar las conversiones.

- **Capa de Presentación (`/ui/screens`):**
    - **`ConverterScreen.kt`:** Nueva pantalla con campos de texto y menús desplegables para la interacción del usuario. Muestra el resultado en una tarjeta destacada.
    - **Acceso a la Pantalla:** Se ha añadido un nuevo ítem, "Conversor de Moneda", en la barra lateral desplegable (`DrawerContent`) para navegar a esta funcionalidad.

**Mejoras y Cambios Recientes (v3.1):**

- **Mejoras en la Experiencia de Usuario (UI/UX):**
    - **Validación de Entrada:** El campo de monto ahora solo acepta valores numéricos, previniendo errores de formato.
    - **Feedback Visual:** `ConverterScreen.kt` muestra un indicador de carga (`CircularProgressIndicator`) mientras la conversión está en proceso. El resultado solo se muestra al completarse.
    - **Intercambio de Monedas:** El botón de intercambio (`swap`) ahora es completamente funcional.
    - **Diseño Consistente:** La tarjeta que muestra el resultado de la conversión ahora utiliza el color `LavenderBlue`, alineándose con la paleta de colores principal de la aplicación.
