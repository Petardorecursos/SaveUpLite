# Documentación de la Funcionalidad de Deudas
**Versión:** 2.0
**Autor:** Rui
**Fecha:** 2024-05-24

Este documento detalla la lógica de negocio y la implementación técnica de la gestión de deudas en el backend de SaveUp Lite.

---
## 1. Lógica de Negocio y Arquitectura

Esta sección describe los principios fundamentales que rigen la funcionalidad de deudas, alineados con la arquitectura general del sistema.

### 1.1. La Entidad `Deuda`
La entidad `Deuda` almacena la información inicial y fija de una obligación financiera.
*   **Atributos Fijos:** `id`, `nombre`, `descripcion`, `montoTotal`, `cantidadCuotas`, `fechaCreacion`, `usuario`.
*   **Atributo de Estado:** `estado` (un Enum `EstadoDeuda`) que refleja su ciclo de vida.

### 1.2. El `EstadoDeuda` (Enum)
Un enum para gestionar el estado de la deuda de forma segura.
*   `PENDIENTE`: La deuda está activa y tiene un saldo restante.
*   `PAGADA`: El total de los pagos asociados iguala o supera el `montoTotal`.
*   `CANCELADA`: El usuario decidió anularla (soft delete).

### 1.3. Conexión Crucial: `Deuda` y `Movimiento`
Este es el pilar de la integridad de los datos:
*   **Registrar un pago de cuota CREA un nuevo `Movimiento`**, no modifica la `Deuda` directamente.
*   Este `Movimiento` tiene:
    *   `tipoMovimiento` = `PAGO_DEUDA`.
    *   `monto` negativo (es un egreso).
    *   Una `ForeignKey` que lo vincula con el `id` de la `Deuda`.

### 1.4. Valores Calculados en Tiempo Real
Los datos de progreso de la deuda no se almacenan; se calculan bajo demanda para garantizar la consistencia.
*   **`montoPagado`**: `SUM(movimiento.monto)` de los pagos asociados.
*   **`montoRestante`**: `deuda.montoTotal - montoPagado`.
*   **`cuotasPagadas`**: `COUNT(*)` de los pagos asociados.

## 2. Implementación en el Backend (Spring Boot)

### Referirse a archivo 'deuda_backend_doc.txt'


### 2.3. DTOs (Data Transfer Objects)
Clases para transferir datos entre el cliente y el servidor de forma segura y validada.

*   **`DeudaCreacionDTO`**: Para recibir los datos al crear o editar una deuda.
*   **`DeudaResponseDTO`**: Para enviar al cliente el estado completo de una deuda, incluyendo los campos calculados.
*   **`PagoDeudaDTO`**: Para recibir los datos de un pago de cuota.

### 2.4. Controlador (`DeudaController`) y Endpoints
Expone la funcionalidad a través de una API REST.

*   **`POST /api/deudas`**: Crea una nueva deuda.
*   **`GET /api/deudas/usuario/{rut}`**: Obtiene la lista de todas las deudas de un usuario.
*   **`POST /api/deudas/{deudaId}/pagar`**: Registra el pago de una cuota para una deuda específica.
*   **`PUT /api/deudas/{deudaId}`**: Edita los detalles de una deuda.
*   **`PATCH /api/deudas/{deudaId}/cancelar`**: Cambia el estado de una deuda a `CANCELADA` (soft delete).

## 4. Implementación en el Frontend (Android - Jetpack Compose)

Esta sección detalla cómo la aplicación Android consume la API de deudas y presenta la funcionalidad al usuario final.

### 4.1. Modelos de Datos (Paquete `model.deuda`)
Se crearon data classes en Kotlin que reflejan la estructura de los DTOs del backend para asegurar una correcta deserialización con Gson.
*   **`Deuda.kt`**: Análogo al `DeudaResponseDTO`. Representa una deuda con todos sus campos, incluyendo los calculados por el backend.
*   **`DeudaCreacion.kt`**: Análogo al `DeudaCreacionDTO`. Se utiliza para encapsular los datos que el usuario ingresa en el formulario de nueva deuda.
*   **`PagoDeuda.kt`**: Análogo al `PagoDeudaDTO`. Contiene el monto y descripción de un pago.
*   **`EstadoDeuda.kt`**: Enum que replica el `EstadoDeuda` del backend para una gestión de estados consistente en el frontend.

### 4.2. Capa de Red (`api.ApiService`)
La interfaz de Retrofit fue extendida para incluir los nuevos endpoints de deudas.
*   `suspend fun crearDeuda(@Body deudaCreacion: DeudaCreacion): Response<Deuda>`
*   `suspend fun obtenerDeudasPorUsuario(@Path("rut") rut: String): Response<List<Deuda>>`
*   `suspend fun registrarPagoDeuda(@Path("deudaId") deudaId: Long, @Body pagoDeuda: PagoDeuda): Response<Deuda>`
*   `suspend fun editarDeuda(...)` y `cancelarDeuda(...)` (definidas para futuras implementaciones).

### 4.3. ViewModel (`DeudaViewModel` y `DeudaViewModelFactory`)
El `DeudaViewModel` orquesta toda la lógica de la UI y la interacción con la capa de red.
*   **`DeudaUiState`**: Data class que representa el estado de la UI (lista de deudas, estado de carga, mensajes de error, etc.).
*   **`obtenerDeudas(rut: String)`**: Llama al `apiService` para obtener las deudas y actualiza el `_uiState` con la lista o con un mensaje de error.
*   **`crearDeuda(deudaCreacion: DeudaCreacion)`**: Envía la nueva deuda al backend y, si es exitoso, dispara la recarga de la lista.
*   **`registrarPago(deudaId: Long, ...)`**: Envía un nuevo pago y recarga la lista para reflejar el progreso.
*   **`DeudaViewModelFactory`**: Clase factory esencial para la inyección de dependencias, que provee la instancia de `ApiService` al `DeudaViewModel`.

### 4.4. Interfaz de Usuario (UI - Jetpack Compose)

#### 4.4.1. `DeudasScreen.kt` (Pantalla Principal)
*   **Estructura**: Utiliza un `Scaffold` con una `TopAppBar`, la `SoftUiBottomNav` compartida y un `FloatingActionButton` para añadir nuevas deudas.
*   **Estado**: Observa el `uiState` del `DeudaViewModel` para mostrar un `CircularProgressIndicator`, un mensaje de error, un mensaje de "sin deudas" o la lista de deudas.
*   **Lista**: Usa una `LazyColumn` para renderizar eficientemente la lista de `DeudaItem`.
*   **Flujo de Pago**: Inicia un diálogo (`PagoDeudaDialog`) cuando el usuario presiona "Registrar Pago".
*   **Corrección de Lógica de Negocio**: Implementa un cálculo en el frontend para las **cuotas pagadas reales** (`cuotasPagadasReales`). Este cálculo (`montoPagado / valorCuota`) sobrescribe el valor `cuotasPagadas` que viene del backend, ya que el backend cuenta transacciones en lugar de progreso real. Esto asegura que la UI siempre muestre el número correcto de cuotas completadas.

#### 4.4.2. `AddDeudaScreen.kt` (Formulario de Creación)
*   **Estructura**: Un `Scaffold` con una barra superior que incluye un botón para volver atrás.
*   **Formulario**: Contiene `OutlinedTextField` para nombre, descripción, monto y cuotas.
*   **Mejoras de Usabilidad**:
    *   **Tabulación (Focus Management)**: Utiliza `FocusRequester` y `KeyboardActions` para permitir que el usuario navegue entre los campos con la acción "Siguiente" del teclado.
    *   **Formato de Monto**: Aplica una `NumberVisualTransformation` personalizada al campo de monto para mostrar separadores de miles mientras el usuario escribe, mejorando la legibilidad.

#### 4.4.3. `PagoDeudaDialog` (Dentro de `DeudasScreen.kt`)
*   **Componente**: Un `AlertDialog` que se muestra al intentar pagar una deuda.
*   **Funcionalidad Avanzada**: Permite al usuario elegir entre tres modos de pago mediante `RadioButton`:
    1.  **Monto Cuota**: Calcula y pre-rellena automáticamente el monto de la cuota (`monto restante / cuotas restantes`). El campo de texto se deshabilita para evitar errores.
    2.  **Varias Cuotas (Nuevo)**: Muestra un selector de cantidad (stepper) que permite elegir pagar múltiples cuotas de una vez.
        *   **Selector Dinámico**: Limitado entre 1 y el número de `cuotas restantes`.
        *   **Cálculo Automático**: El monto se actualiza en tiempo real (`valorCuota * cantidadSeleccionada`) y el campo permanece en modo solo lectura.
        *   **Descripción Inteligente**: Genera automáticamente una descripción de rango (ej. "Pago cuotas 3 a 5").
    3.  **Monto Personalizado**: Permite al usuario ingresar un monto diferente libremente.
*   **Interacción con Backend**: Independientemente de la opción, se envía una única transacción `PagoDeuda` al backend. La lógica del servidor procesa el monto acumulado sin necesitar cambios en la API.
*   **Lógica de Cálculo**: Utiliza el cálculo de `cuotasPagadasReales` para asegurar que el selector de cuotas y las descripciones sugeridas sean siempre precisas, incluso si hubo pagos parciales previos.
